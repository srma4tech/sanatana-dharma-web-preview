# Approved Content Integration Contract

## Purpose

Provide a small, predictable access layer between the validated release dataset and future bilingual page templates. Keep the UI and editorial workflow separate.

## Source of truth

- Runtime pages may consume only `src/data/published-content.json`, generated by `scripts/prepare-content-release.mjs`.
- The three Shiva JSON files under the content repository's `docs/review-drafts/structured-json/` are editorial review artifacts. They are not imported by the website and are not canonical release records.
- The website must not infer approval from a draft's existence, a successful CI run, or a merged documentation PR.

## Access layer

`src/lib/published-content.js` exposes:

- `getPublishedContent(dataset, locale)`: returns records only when the dataset is marked `validated`, the locale is supported, the record is published, and that locale's language and subject gates are approved.
- `getPublishedContentBySlug(dataset, locale, slug)`: finds a record only inside that approved subset.

The helpers fail closed to an empty result for missing, malformed, unconfigured, or unsupported input.

## Page integration sequence

1. Keep the existing home and library layouts unchanged while adding the data layer.
2. After schema governance is approved, map reviewed JSON drafts into canonical entity records with stable IDs, locale-specific content, source references, slugs, and editorial metadata.
3. After independent subject review, separate English/Hindi review, source verification, rights checks, and explicit release approval, construct a release manifest and hashes.
4. Let the existing release validator produce the validated dataset.
5. Add locale-specific static routes and empty states using the access layer; never read review-draft files directly from public page code.
6. Run build, accessibility, direct-link, locale parity, and publication-gate tests before preview deployment.

- All three Shiva JSON drafts remain non-canonical and not approved for publication.
- No content is being published by this change. No schema, existing UI, release manifest, or deployment configuration is changed.
